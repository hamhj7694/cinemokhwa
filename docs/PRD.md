## 1. 제품 개요

### 1.1 한 줄 정의

> **"목소리 하나로, 영상 한 편."**
> 사람이 녹음한 목소리를 입력하면, 로컬 AI가 장면을 나누고 그림을 그리고 움직이고 입모양을 맞춰 **최종 1080p 영상 파일**까지 만들어 주는 데스크톱 로컬 앱.

### 1.2 무엇이 다른가

| 기존 도구 | 씨네목화 |
|---|---|
| 스톡 클립을 잘라 붙임 (MoneyPrinterTurbo 계열) | **픽셀을 직접 생성** (Wan 2.2 I2V) |
| 클라우드 유료 API (Seedance·Kling·Runway) | **로컬 추론, API 키 0개, 무제한** |
| 텍스트 → 영상 (audio 나중에) | **음성 우선**: 녹음이 먼저, 영상이 목소리에 맞춰 생성 |
| 장르 프리셋 없음 / 파라미터 폭탄 | **5개 장르 프리셋** + 챗봇 대화로 기획 |
| 결과물만 던져줌 | **단계별 진행률·예상 시간·재개 가능** |

### 1.3 슬로건 · 브랜딩

- 슬로건: **"목소리로 짓는 영화"**
- 뿌리 문장: "말이 씨가 되어 영화가 된다"
- 브랜드 계층: 씨네목화(제품) / 목화씨네 영화관(캠페인) / 목화 스튜디오(편집 화면) / 목화 창고(보관소)

## 2. 문제 정의

### 2.1 지금 영상 제작이 어려운 이유

1. **비용**: 생성형 영상 API는 초 단위 과금. 30초 1편에 수천 원~수만 원. 반복 실험이 불가능.
2. **종속**: 모델·가격·정책이 플랫폼 마음대로 바뀜. 만든 워크플로가 사라짐.
3. **음성 부재**: 대부분 텍스트→영상. "내 목소리로 만든 영상"은 별도 툴 3~4개를 거쳐야 함.
4. **파편화**: 대본(GPT) → 이미지(Midjourney) → 영상(Runway) → 립싱크(HeyGen) → 편집(Premiere) → 자막(별도). 5개 구독.
5. **낯섦**: 로컬 모델은 설치·VRAM·워크플로 지식이 필요해 비개발자가 못 씀.

### 2.2 우리가 푸는 문제

> **"돈과 구독 없이, 내 목소리로, 한 화면에서, 끝까지."**

## 5. 대상 사용자

### 5.1 1차 사용자 (이 제품의 유일한 사용자)

> **"혼자 만드는 크리에이터" — 이 PC의 주인.**
> 영상 편집은 조금 알지만 AI 모델 설치는 어려워하고, 구독료에 지쳤으며, 자기 목소리로 콘텐츠를 만들고 싶은 사람.

| 속성 | 값 |
|---|---|
| 규모 | 1명 (본인) |
| 기기 | Windows 10 · RTX 3060 12GB |
| 예산 | 0원 (전기세 제외) |
| 기술 수준 | CLI는 무서워함, 웹 UI는 능숙 |
| 시간 | 1편에 1시간까지 허용 |

### 5.2 2차 사용자 (V2 이후 확장 여지)

- 지인 크리에이터 (같은 PC를 돌려 쓰는 형태)
- 교육용 설명 영상 제작자
- 소규모 브랜드의 제품 소개 영상 담당자

### 5.3 사용자가 원하는 것 / 싫어하는 것

| 원함 | 싫어함 |
|---|---|
| 말로 설명하면 알아서 기획 | 옵션 30개를 직접 채우기 |

| 결과물이 바로 올릴 수 있는 규격 | 코덱·비율 수동 변환 |

## 6. 핵심 사용자 시나리오

### SC-1. 나레이션 다큐 (주 시나리오)

```
1. 앱 실행 → 첫 화면 챗봇
2. "제주 바다 다큐 30초, 차분하게" 입력
3. AI: 장르/톤/자막/BGM 후보 제시 → 3턴 대화로 스토리보드 6장면 확정
4. [제작] 탭 → 마이크로 대본 낭독 (0:31)
5. 자동 분석 → 6구간 + 자막 초안 → 사용자 확인·수정
6. [영상 생성] → 단계별 진행률 확인 (약 55분)
7. 결과 화면 → 장면 2개만 마음에 안 듦 → 해당 장면 재생성
8. 자막 스타일 "다큐" 선택, BGM 자동 매칭 확인 → 내보내기(유튜브)
9. output/jeju_30s_1080p.mp4 완성
```

**성공 조건**: 4번에서 녹음만 하면 나머지가 자동. 6번에서 남은 시간이 보임. 7번에서 전체 재실행 없음.

### SC-2. 숏폼 9:16 (빠른 템포)

```
1. "빈티지 카페 오픈 홍보 숏폼 15초, 신나게" 
2. 프리셋 📱숏폼 자동 선택 → 9:16 · 3~5초 클립 · 카라오케 자막 · 비트 BGM
3. TTS로 대본 생성 (녹음 생략) — 경로 T
4. 장면 4개 생성 → 중앙 큰 자막 자동
5. 내보내기(숏폼) → 1080×1920
```

**성공 조건**: 프리셋이 비율·자막·BGM·화풍을 한 번에 세팅. 사용자가 건드리는 값 ≤ 2개.

### SC-3. 대사 드라마 (다화자)

```
1. "두 사람 대화로 된 30초 드라마, 따뜻하게"
2. 경로 D 선택 → 자유 대화 녹음 (A/B 두 목소리)
3. pyannote 화자분리 → 화자별 색 구분된 자막
4. 장면별 등장 캐릭터 지정 (목화 창고에서 2명 선택)
5. 인물 장면만 립싱크, 풍경 장면은 B롤
6. 내보내기
```

**성공 조건**: 화자분리가 90% 이상 정확. 캐릭터가 장면 간 동일하게 보임.

### SC-4. 실패 복구

```
1. 영상 생성 중 ComfyUI 크래시
2. UI: "장면 3/6 실패 — 모델 누락: wan2.2_vae.safetensors"
3. [모델 다시 받기] 클릭 → 매니페스트 기반 재다운로드
4. [이어서 생성] → 장면 3부터 재개, 1~2는 캐시 사용
```

**성공 조건**: 크래시 후 1클릭으로 재개. 이미 만든 장면 재생성 0회.

## 7. 기능 요구사항 (Functional Requirements)

> 우선순위는 **MVP 기준**. M1~M8 태그는 해당 마일스톤에서 동작해야 함을 의미.

### FR-01 프로젝트 생성·관리 — M1 · **M**

| 항목 | 내용 |
|---|---|
| 목적 | 모든 산출물을 프로젝트 단위로 격리 |
| 입력 | 이름, 장르 프리셋, 비율 |
| 동작 | `projects/<slug>/` 생성, `project.json`(메타) + `state.json`(진행) 초기화 |
| 출력 | 프로젝트 목록/최근 프로젝트 |
| 수용 기준 | ① 새 프로젝트 생성 시 폴더 구조 자동 생성 ② 앱 재시작 후 목록 유지 ③ 프로젝트 삭제 시 확인 다이얼로그 ④ 이름 중복 시 자동 suffix |

### FR-02 장르 프리셋 — M2 · **M**

| 항목 | 내용 |
|---|---|
| 목적 | 장르 선택만으로 6개 파라미터 세팅 |
| 입력 | 프리셋 선택 (영화/드라마/숏폼/다큐/설명) |
| 동작 | `config/presets/*.toml` 로드 → 비율·클립 길이·페이스·자막 스타일·목소리 톤·기본 화풍·BGM 무드 적용 |
| 출력 | 프로젝트 설정 + 스토리보드 기본값 |
| 수용 기준 | ① 5종 모두 로드 ② 프리셋 적용 후 사용자가 개별 값 오버라이드 가능 ③ 오버라이드 값은 프로젝트에 저장 ④ 사용자 정의 프리셋 파일 추가 가능 |

### FR-03 챗봇 기획 — M4 · **M**

| 항목 | 내용 |
|---|---|
| 목적 | 파라미터를 몰라도 대화로 기획 완성 |

| 입력 | 완성 길이(30초/1분/3분/10분/직접) · 장면당 길이(고급, 기본 자동) · 전환(0.3/0.5/0.8초/없음) |
| 동작 | 완성 길이 → 장면 수 자동 산출 → 클립 N개 생성(체이닝) → concat + 크로스페이드 → 완성본. 진행률은 클립 개수가 아니라 **완성 길이 기준 %** 로 표시 |
| 출력 | `final.mp4` 1개 + `timeline.json` |
| 수용 기준 | ① 완성 길이 오차 ≤ ±2초 ② 클립 경계 이음새가 육안으로 두드러지지 않음(체크리스트) ③ 3분 설정 시 E2E 1회 성공 ④ 진행률이 완성 길이 % ⑤ "없음" 선택 시 하드컷 ⑥ 클립 길이는 UI 기본 화면에 노출하지 않음 |

## 8. 데이터 요구사항

### 8.1 프로젝트 폴더 구조

```
projects/<slug>/
  project.json          # 메타: 이름·프리셋·비율·화풍·언어·생성일
  state.json            # 단계별 진행 상태 스냅샷(D45)
  storyboard.json       # 기획 산출물
  production.json       # 제작 산출물 (구간·장면·캐릭터 연결)
  characters/
    <id>.json           # 캐릭터 카드 + versions[]
    refs/<id>_v1.png
  audio/voice.wav
  work/<run_id>/         # 키프레임·클립·중간 파일(캐시)
  output/final_*.mp4
```

### 8.2 핵심 스키마 (요약 — 상세는 DESIGN §10)

| 파일 | 필수 필드 |
|---|---|
| `storyboard.json` | `title, language, aspect, style, scenes[{id, narration, caption, visual_prompt, negative_prompt, seed, seconds}]` |
| `production.json` | `audio, total_duration, characters[{id,name,desc,ref}], scenes[{id,start,end,speaker,text,visual_prompt,lip_sync,clips[]}]` |
| `characters/<id>.json` | `id, name, desc, style, versions[{v,seed,refs[],created_at}], current_v` |
| `bgm/<track>.json` | `id, mood[], genre[], bpm, duration, path` |
| `state.json` | `run_id, stages{script,audio,analyze,keyframe,video,lipsync,upscale,assemble}{status,started,ended,hash,artifacts[]}` |

### 8.3 데이터 원칙

1. **append-only**: 캐릭터 버전·실행 로그는 덮어쓰지 않는다.
2. **재현성**: 모든 생성물에 시드·모델명·파라미터를 기록한다.
3. **미디어 분리**: `state.json`은 미디어를 참조만 한다(수 KB).
4. **경로 상대화**: 프로젝트 내부 경로는 상대 경로로 저장(이동 가능).
5. **인코딩**: JSON은 UTF-8(BOM 없음), 텍스트 산출물은 LF.
