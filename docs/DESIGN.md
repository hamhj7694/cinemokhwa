> 상태: **설계 중 (구현 미착수)** · 최종 수정: 2026-11-13
> 이 문서는 처음부터의 모든 결정을 통합·정돈한 단일 설계 기준서입니다.
> 프로젝트 이름은 미정이며, 정해지면 `<PROJECT>/docs/DESIGN.md`로 이동합니다.

## 1. 비전

**완전 무료 · 무제한 · 로컬**에서 동작하는 AI 영상 제작 플랫폼.
외부 유료 API 키 없이, 주제 한 줄 또는 사람의 목소리로부터 **영상 픽셀까지** 생성한다.

### 목표
- 픽셀 생성까지 가능 (스톡 영상 대체가 아님)
- 다양한 장르/규격: 영화 · 드라마 · 숏폼(9:16) · 다큐 · 설명 영상 등 **선택형**
- **챗봇 우선** UI: 자연어로 대화하며 기획
- **음성 우선(voice-first)** 제작: 사람 목소리(녹음)에 맞춰 영상·입모양 생성
- 관리자 권한 없이도 동작 (포터블/사용자 설치) — 실측상 계정은 관리자 자격 보유, 포터블은 "안전해서" 선택 (D48)

### 비목표 (명시적 제외)
- 클라우드 생성 API(Seedance/MiniMax 등) 의존 — 무료·로컬 원칙 위배
- MoneyPrinterTurbo — 생성형 영상이 아니라 기존 클립 자동 편집·조립 툴이며 영상 생성은 클라우드 API 전용
- 14B/대형 영상 모델(HunyuanVideo, LTX-2.3 등) — 이 PC의 12GB VRAM에서 비현실적

## 3. 핵심 원칙

1. **로컬 우선**: 외부 API 키 0개. 모든 추론은 이 PC.
2. **오디오 우선**: 음성 모드에서는 **녹음이 먼저**, 영상이 그 길이·내용에 맞춰 생성.
3. **단계 직렬 실행**: 대본 → (언로드) → 영상 → 립싱크. VRAM 충돌 방지.
4. **캐시·재개**: 단계별 산출물 저장, 변경된 단계만 재실행.
5. **모델 수명 관리**: Ollama는 `keep_alive: 0`으로 명시적 언로드(자동 5분은 부족).
6. **상업 안전**: 라이선스 확인된 모델만 채택(Wav2Lip OSS 제외).

### 7.2 제작 단계 (Production)

진입 경로 3가지 — **모두 "오디오가 먼저 확정"**:

| 경로 | 입력 | 대본 | 화자 | 용도 |

```

        │
```

### 7.3 길이 매칭 전략
Wan 2.2 5B는 프레임 수 가변(4n+1)이 가능 → 오디오 구간에 정확히 맞춤.

| 오디오 구간 L | 전략 |
|---|---|
| ≤ 5.5s | 클립 1개, 프레임 = L×24 (4n+1 반올림) |
| 5.5–11s | 5초 클립 2개 체이닝 |
| > 11s | 5초 클립 n개 체이닝 (장면 분할 권장) |

### 7.4 장면 일관성 (D8 + D20 + D30)
1차: **키프레임 + IPAdapter** (D20) — 캐릭터 레퍼런스 이미지를 각 장면 첫 프레임 생성에 주입 → 캐릭터 외형 고정.
2차: **체이닝** (D8) — 앞 클립 마지막 프레임을 다음 클립 첫 프레임으로(I2V) → 장면 연속.
화풍: **실사 ↔ 애니 토글** (D30) — 한 프로젝트 내에서 화풍을 고정(중간 전환 시 이질감). 프롬프트 접두도 화풍별로 분리.
보조: 프로젝트 고정 시드 계열 + 동일 `style` 접두 + 캐릭터 설명 고정.

### 7.5 립싱크 (역방향 더빙)
- 인물 클로즈업 장면에만 적용. 풍경/사물 장면은 생략(나레이션+B롤).
- **원본 녹음 오디오를 유지**하고 입모양만 재생성.
- 엔진 선택: 빠름=MuseTalk, 고품질=LatentSync 1.5, 사진 1장=SadTalker.

## 12. 운영 정책

- **캐시/재개**: `work/<run_id>/`에 단계별 산출물, 변경 단계만 재실행.
- **모델 수명**: 대본 단계 후 Gemma `keep_alive:0` 언로드 → Wan 로드.
- **오류 처리**: ComfyUI 미실행/모델 누락 시 명확한 메시지 + 모델 다운로더 제공.
- **로그**: 실행 ID, 단계, 소요 시간, 사용 모델·파라미터 기록.
- **성능 예산(M-A, 12GB)**: 5초 클립 = **21.7분**(1280×704·25스텝·I2V 실측) → **30초 ≈ 2시간 15분**, 1분 ≈ 4.5시간. T0 보조컷은 30초 3~5분(D61). M-B = 자동 15~30분 + 사람 수정 12~30분. M-C = 에셋 재사용 시 30~60분. 녹음 우선으로 총 길이 확정 후 **모드별** 예상 시간 안내.
- **출력 파이프라인(품질 우선)**: 키프레임(SDXL) → I2V(Wan) → (립싱크) → **Real-ESRGAN 1920×1080** → 자막/BGM 조립.
- **화질 원칙**: 네이티브에서 최고 화질로 뽑고, 업스케일은 Real-ESRGAN 사용(시간이 더 걸려도 품질 우선).
- **실행 환경**: 이 PC 단독 로컬. 단일 런처로 백엔드(FastAPI)+프론트(Vite) 기동.
- **모드별 한계(D59)**: M-A = 영상 내 텍스트 불가(자막으로 해결)·드리프트·손/얼굴 아티팩트·장면 일관성 약함·704p→업스케일 / M-B = 레이어 수정에 사람 손 필요(반자동)·임의 피사체 불가 / M-C = 에셋 준비가 병목·AI 생성 메시는 리깅 부적합 / T0 = 피사체 움직임 없음(카메라만). 공통: 기본 오디오 없음.

## 17. 브랜딩 / 네이밍 (검토 중)

### 17.1 포지셔닝 (뿌리)
- **voice-first**: 사람 목소리가 출발점(녹음 우선 → 영상 생성).

- 방향: **"말이 C(Creative)가 된다"** — 말 → 창작물.

### 17.2 슬로건 (초안)
- KR: **"말이 씨앗이 된다."** / **"말 한마디가 영상으로 자란다."**
- EN(보조): *From voice to vision.* / *Words become worlds.*
- (언어 메인 확정은 보류 — 사용자)

### 17.3 네이밍 검토 메모 (근거)
| 검토 | 결론 |
|---|---|
| `톡` 사용 | ⚠️ **회피 권장** — ByteDance `TIK TOK` 상표(클래스 9·38·41·42)와 충돌, 영상 도구는 41·42 정면 겹침, WIPO 분쟁 다수 |

### 17.5 동음이의·언어유희 후보 (당근마켓 방식)
> 원리: **과일·채소(표면)** + **영상/영화 동음이의(숨은 뜻)** → 기억에 남고 브랜드 스토리가 생긴다.

| 후보 | 분해 | 숨은 뜻 / 언어유희 | 브랜드 스토리 | 상표력 |
|---|---|---|---|---|
| **영상추** ⭐ | 영상 + 상추 | "video + lettuce" (상 공유) | "말이 자라 영상추가 되는 밭" | 조어(강) |

| **배우** | 배 + 우 | 배우(actor) | "모든 배(pear)가 배우(actor)가 된다" | 약(일반어) |
| **감독** | 감 + 독 | 감독(director) | "감(감)이 감독이 된다" | 약(일반어) |

**원칙**
- 뿌리는 `목화` 하나. 모든 파생 이름은 `목화`로 시작(씨네목화·목화씨네 영화관·목화 스튜디오·목화 창고) → 통일성 유지.
- `씨네`는 카테고리 접두어(씨네큐·씨네드쉐프 계열)로 읽힘. `씨네목화` = "목화 시네마", `목화씨네` = "목화의 집". 어순이 역할(도구 ↔ 공간)을 표현.
- **줄임말 금지**: 제품은 항상 `씨네목화`, 캠페인은 항상 `목화씨네 영화관`. 한쪽을 `목화`/`씨네`로 축약하지 않음.
- **시각 구분**: 제품 = 워드마크 + 앱 아이콘 / 캠페인 = 목화꽃 심볼 + 별도 색.
- 상표: `목화` 단독은 일반명사 → 워드마크(MOKHWA) + 로고 결합상표로 보호. KIPRIS 41·42류 확인 필요.
- 검색 노이즈: `목화` = 면화(棉花) → 모든 메타데이터에 **"목화 | 목소리로 짓는 영화"** 병기. 도메인은 `.film`/`.app` 우선.
