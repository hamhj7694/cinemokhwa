## 표준 평가용 사례(합성·사용 권한 확보된 참조만 사용)
- **S1 구조 동작:** 한 명(회색 원기둥 proxy), 평평한 배경, 3초; 카메라 고정, 대상 왼쪽→오른쪽 이동. 목표: 영상의 가로 이동과 프리비즈 트랙이 비슷한지.
- **S2 카메라 동작:** 한 명, 5초; 객체는 고정, 카메라 dolly 또는 pan. 목표: 카메라 vs 객체 이동 혼동 방지.
- **S3 외형 정체성:** 기준 사진 1장, 동일 인물 서로 다른 각도. 목표: 1~2초 간격의 얼굴/의상 유지 및 얼굴 없는 프레임 별도 처리.
- **S4 물체 가림(후속 H4):** 인물 1명+가방 1개, 가방이 잠시 가렸다 재등장. 목표: ID와 위치 추적.
- **S5 다샷(후속 H5):** 동일 인물·장소의 2~3샷. 목표: 샷별 색/조명/정체성·컷/연장.
- **S6 실패 복구:** 모델 없음, 참조 권한 누락, 잘못된 스키마, 프레임 누락, 중간 OOM. 목표: 실패를 성공으로 쓰지 않고 변경된 stage만 재실행.

## 지표/판정 기준
| 분류 | 측정 | 초기 판정 원칙 |
|---|---|---|
| 구조 | 입력 프레임 수, ID, 샷 길이, camera/track 수, 앵커 인덱스 | 입력 계약 위반 시 자동 FAIL. 회귀 fixture는 100% 일치 |
| 위치/궤적 | 프리비즈 vs 생성 영상의 bbox 중심·크기 변화, 객체 ID 매칭 | 정규화 오차 평균 0.10 이내 **실험 가설**. 탐지 실패/가림은 '측정 불가'로 따로 관리 |
| 얼굴 | 참조 이미지 vs 결과 프레임 SFace 유사도 | 0.60은 시작 **후보 임계값**, 모델·각도별 보정 필요. 얼굴 없음/null은 PASS 아님 |
| 밝기 | 장면 내 깜빡임, 장면 간 평균 Y | P1 지표와 비교. 자연스러운 조명 변화와 고주파 깜빡임 분리 |
| 프레임 | 움직임 안정/변형/잔상/손/소품 오류 | 사람 육안 5개 항목 각각 1~5 평가, 치명적 결함은 수치와 무관하게 FAIL |
| 연속성 | 3~5초 내 대상 동일성, 다샷 cut 연결 | 시작/끝+중간 여러 시점 반드시 검토 |
| 성능 | 벽시계, peak VRAM, FPS, 해상도, GPU/모델, OOM | 환경/선택 조건을 정확히 기록. 속도 목표 미달 ≠ 화질 실패 |
| 라이선스 | 모델·가중치·참조 출처와 사용권한 | 미확인/비허용인 경우 상업 사용 승인 불가 |

**사람 육안 항목:** (1) 인물 동일성 (2) 3D 목표 동작과 유사성 (3) 인물·물체 위치/크기 (4) 외형/시간적 안정성 (5) 조명·화질·카메라 자연스러움. 모든 항목에 짧은 근거와 실패 프레임 시각을 남긴다.

## A/B 테스트 실험 설계
- **실험 A:** 동일 모델/seed/첫 실사 프레임에서 3D guide **미사용 vs 사용** 비교. 객체 이동·카메라 경로 변화가 유의하게 개선되는지 기록.
- **실험 B:** 동일 참조 이미지에서 서로 다른 reference strength/anchor interval만 변경. 얼굴 유사성과 동작 유지의 상충관계를 측정.
- **실험 C:** Krea2 vs SDXL 이미지 앵커 (상업 허용/모델 준비 조건에 한함). Qwen21은 코드 연구 경로로 남겨두되 사용권 검토 전 상업 결과에 활용하지 않는다.
- **실험 D:** LTX Q3 vs Q2/해상도/짧은 세그먼트. 실제 렌더 시간과 얼굴·동작·화질 저하 정도 병행 측정.

A/B는 **한 번에 한 변수만 바꾸기**. 보고서에 참고 이미지/환경/정확한 seed, frame indices, 모델 체크섬, 비용(시간)을 포함한다.

## 기준 실측(기존 문서에서만 확인)
- P1 `guided-50`: 3씬 14.54초 생성 57.0분, 자동 WARN(FAIL 없음). 이는 **성공적 시각 일관성의 증거가 아님**.
- P2 독립 스모크: Krea2 사진 1장 65.1초, Qwen21 사진 1장 230.2초, LTX 25f 530.5초. **3D 가이드의 제어 효과 검증이 아님**.
- LTX 121프레임/15초 환산 수치는 선형 근사일 뿐 실제 GPU/메모리 사용·후처리와 다를 수 있다. 파일럿 전에 15초 ≤70분 PASS라고 쓰지 않는다.

## PR/릴리스 필수 게이트
- PR: 변경 코드 compile + 계약/단위 테스트 + 실패 경로 + docs update + no generated assets committed.
- 실험 PR: 재현 명령과 run_id/조건/실측을 WORKLOG에 기록.
- H3 이후 릴리스: T0~T4 완료, T5 verdict=accepted. `pending`, `WARN`, `needs_review`는 정식 품질 합격 아님.
- 사용자에게 실제 영상 샘플을 보여주지 못했다면 **검증 불가**로 명시.
