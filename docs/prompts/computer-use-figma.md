# 컴퓨터 유즈 Figma 디자인 프롬프트 (재사용 템플릿)

> 버전 v1 · 2026-11-17
> 용도: Figma MCP 없이 **브라우저/컴퓨터 유즈**로 Figma UI를 직접 조작해 디자인한다.
> 관계: `design-to-figma-playbook.md`(공식·함정·체크리스트) + 이 문서(실행 프롬프트).
> 디자인 계획안이 없으면 `design-to-figma-playbook.md` **Part C-2**를 먼저 실행한다.

## 치환 변수

| 변수 | 의미 | 예시 |
|---|---|---|
| `{{PROJECT_NAME}}` | 대상 프로젝트 이름 | `씨네목화` |
| `{{PRD_PATH}}` | PRD 경로 | `docs/PRD.md` |
| `{{DESIGN_PLAN_PATH}}` | 디자인 계획안 경로 | `docs/design/DESIGN-PLAN.md` |
| `{{FIGMA_URL}}` | 기존 Figma 파일 URL | `https://figma.com/design/...` |
| `{{FRAME_SIZE}}` | 기준 해상도 | `1440×900` |
| `{{THEME}}` | 기본 테마 | `다크` |

## 사용법

1. 대상 프로젝트에 **PRD**와 (있으면) **디자인 계획안**을 첨부한다.
2. 계획안이 없으면 `design-to-figma-playbook.md` Part C-2로 먼저 작성·승인한다.
3. 아래 코드 블록의 `{{...}}`를 치환해 새 세션에 붙여넣는다.
4. 에이전트가 **STEP 0 보고 → "계속" → STEP 1…** 순으로 한 단계씩 진행한다.
5. 첫 검증은 **작은 화면 1개**(예: 설정 화면)로 워크플로를 확인한 뒤 전체로 확장한다.

## 주의

- 컴퓨터 유즈는 MCP보다 느리고 오류가 많다. **한 번에 한 단계만** 진행한다.
- 로그인/2차 인증은 사용자에게 요청하고 멈춘다. 비밀번호를 추측하지 않는다.
- 같은 동작이 2회 실패하면 "차단됨 + 사유 + 화면 캡처 + 우회안"으로 보고한다.
- Figma 자동 저장을 믿되, 단계 완료 후 **파일 URL + 화면 캡처**로 확인한다.

---

```text
[역할]
너는 시니어 프로덕트 디자이너이자 Figma 직접 조작자다.
이번 작업은 Figma MCP(use_figma)가 아니라 **브라우저/컴퓨터 유즈**로
Figma 웹(또는 데스크톱 앱) UI를 직접 조작해 디자인을 만든다.
문서의 방향을 그대로 옮긴다. 새로운 테마/방향을 제안하지 않는다.

[대상 프로젝트]
- 이름: {{PROJECT_NAME}}
- PRD: {{PRD_PATH}}
- 디자인 계획안: {{DESIGN_PLAN_PATH}}   (없으면 "없음"이라고 답하고 C-2를 먼저 실행)
- Figma 파일: {{FIGMA_URL}}   (없으면 새 파일 생성)
- 기준 해상도: {{FRAME_SIZE}}   (기본 1440×900)
- 테마: {{THEME}}   (기본 다크, 라이트는 별도 컬렉션)

[절대 규칙]
1. 사용 가능한 도구를 먼저 확인한다. 브라우저/컴퓨터 유즈 도구가 없으면
   추측하지 말고 멈추고 보고한다.
2. Figma MCP 도구(use_figma 등)를 쓰지 않는다. UI 클릭·입력·단축키로만 조작한다.
3. 클릭 전에 반드시 스냅샷/스크린샷으로 현재 화면을 확인한다. ref를 추측하지 않는다.
4. 로그인/2차 인증이 필요하면 사용자에게 요청하고 멈춘다. 비밀번호를 추측하지 않는다.
5. 한 번에 한 페이지/한 보드/한 컴포넌트 묶음만 만든다. 각 단계 끝에 보고하고 멈춘다.
6. 같은 동작이 2회 실패하면 더 시도하지 말고
   "차단됨 + 사유 + 화면 캡처 + 우회안"으로 보고한다.
7. 저장은 Figma 자동 저장에 맡기되, 단계 완료 후 파일 URL과 화면 캡처로 확인한다.
8. 컴퓨터 유즈는 MCP보다 느리고 오류가 많다.
   작은 화면 1개로 먼저 검증한 뒤 확장한다.

[먼저 읽고 뽑을 것 — 아직 Figma는 건드리지 않는다]
두 문서를 끝까지 읽고 아래를 표로 보고해라.
- 화면 목록(ID·이름·목적·핵심 상태)
- 컬러/타이포/스페이싱/라디우스/그림자 토큰
- 컴포넌트 인벤토리(이름·변형·상태)
- 금지 규칙
- 문서에 없는 값은 "미정"으로 표시하고 질문한다.

[Figma 작업 순서 — 컴퓨터 유즈]
STEP 0. 파일/로그인 확인
- 브라우저로 Figma를 연다. 로그인 상태와 파일 접근 권한을 확인한다.
- 파일이 없으면 새 파일을 만들고 URL을 보고한다.
- 보고: 파일 URL, 현재 페이지 목록, 플랜(페이지/변수 모드 한도) 확인 결과.

STEP 1. 페이지 골격
- 플랜 한도에 맞춰 페이지를 압축한다
  (Starter=3: 01 Design System / 02 Screens / 03 Handoff).
- 기존 페이지가 많으면 이름을 재사용하고 새로 만들지 않는다.
- 페이지 전환은 UI로. 보고: 페이지 목록과 각 페이지 프레임 수.

STEP 2. 토큰
- Variables: Primitives(Value) → Semantic Color(다크) →
  Color Light(라이트, 별도 컬렉션) → Spacing → Radius.
- Text Styles: 실제 존재하는 폰트만. 폰트가 없으면 폴백을 정하고 보고한다.
- 모든 색은 변수에 바인딩. hex 하드코딩 금지.
- 보고: 컬렉션 목록/모드, COLOR·FLOAT 변수 개수, 텍스트 스타일 목록.

STEP 3. Foundations 보드
- 브랜드 / 컬러 / 타이포 / 스페이싱·라디우스 보드를 만든다.
- 각 보드 생성 직후 넘침(자식이 프레임 밖)을 오른쪽 패널 X/Y/W/H로 확인하고 0으로 만든다.
- 보고: 보드별 크기와 넘침 검사 결과(0이어야 함).

STEP 4. 컴포넌트
- Auto Layout 컴포넌트를 계층형 이름으로 만든다(Button/Primary).
- 순서: 버튼 → 인풋 → 상태 → 챗 → 카드 → 내비.
- 높이 붕괴(10px) 확인. 오토레이아웃 적용 순서(resize 먼저, sizingMode 나중)를 지킨다.
- 보고: 컴포넌트명과 실제 크기 목록(높이가 10이면 실패).

STEP 5. 화면
- 핵심 화면부터: S1 → S2 → S3 → 나머지.
- 기준 해상도, 120px 간격 그리드. 각 화면 생성 직후 넘침/겹침을 수치로 감사.
- 화면당 primary 액션 1개.
- 보고: 화면별 프레임 크기, 주요 영역 좌표, 넘침 0.

STEP 6. 상태·플로우
- 상태 4종(빈/로딩/에러/부분성공) + 핵심 플로우 3~4개를 같은 페이지 섹션에 만든다.
- 보고: 만든 상태 프레임 수, 플로우 수.

STEP 7. Handoff
- 토큰 표, 컴포넌트 인벤토리, 구현 매핑
  (React/Tailwind/shadcn/CSS 변수 이름 규칙), 열린 이슈.
- 마지막에 전체 요약: 페이지·프레임 목록, 미완성 항목과 이유, 문서와 달라진 결정.

[검증 — 매 단계]
- 스크린샷으로 시각 확인 + 오른쪽 패널의 X/Y/W/H로 수치 확인.
- 모든 색: 변수 바인딩 여부.
- 모든 프레임: 자식이 밖으로 나가지 않는지.
- 금지: 이모지 아이콘, 보라→파랑 그라데이션, 글래스모피즘, 네온,
  카드 안 카드, 화면당 primary 2개 이상, 정보 6줄 초과,
  eyebrow 라벨, tracked capitals.
- 한국어 라벨, 번역투 금지. 숫자·시간·로그는 Mono 스타일.

[보고 형식 — 매 STEP]
- 만든 것(이름/개수)
- 검증 숫자(프레임 크기, 넘침 0, 변수 바인딩 수)
- 다음 STEP
- 막힌 것: "차단됨 + 사유 + 화면 캡처 + 우회안"
보고 후 반드시 멈춘다. 내가 "계속"이라고 할 때만 다음 STEP으로 간다.

[첫 응답]
지금은 아무것도 만들지 말고,
① 읽은 문서 요약
② 화면/토큰/컴포넌트/금지 규칙 표
③ Figma 파일·로그인·플랜 확인 결과
④ 3페이지 계획
만 보고하고 멈춰라.
```
