## 0. 이 스킬이 하는 것 / 하지 않는 것

| 전이된다 (방식) | 전이되지 않는다 (대상 문서가 결정) |
|---|---|
| 10단계 공정 | 브랜드 컬러·타이포 |
| 토큰 우선·컴포넌트 우선 | 화면 구성·카피 |
| 수치 검증·핸드오프 | 제품별 컴포넌트 종류 |
| 단계별 승인·정지 | Figma 플랜 한도(적응 필요) |
| 금지 규칙(anti-slop) | 최종 육안 판정 |

> 핵심: **공식은 전이되고, 결과물의 개성은 대상 프로젝트의 `DESIGN-PLAN.md`가 만든다.**

## 1. 공식 한 줄

```text
문서 → 계획 → 프로브 → 토큰 → 기초 보드 → 컴포넌트 → 화면 → 상태/플로우 → 수치 검증 → 핸드오프
```

## 2. 10단계 (입력 / 행동 / 출력 / DoD)

| # | 단계 | 입력 | 행동 | 출력 | DoD (숫자·판정) |
|---|---|---|---|---|---|
| 0 | 문서 읽기 | PRD, DESIGN-PLAN | 화면·토큰·컴포넌트·금지 규칙 추출 | 1장 요약 | 문서에 없는 값은 "미정" |
| 1 | 계획 | PRD | 계획안이 없으면 C-2로 작성 | DESIGN-PLAN | 사용자 승인 |
| 2 | 프로브 | Figma/도구 | 플랜·폰트·도구 확인 | 프로브 표 | 페이지·모드 한도, 폰트 폴백 |
| 3 | 페이지 | 프로브 | 한도에 맞춰 압축 | 페이지 골격 | 페이지 수 = 한도 |
| 4 | 토큰 | DESIGN-PLAN | Primitives→Semantic→Light→Spacing/Radius→Text Styles | Variables/Text Styles | 하드코딩 0, 변수 개수 기록 |
| 5 | 기초 보드 | 토큰 | 브랜드/컬러/타이포/스페이싱 | 보드 4~5장 | 넘침 0 |
| 6 | 컴포넌트 | 토큰 | Auto Layout, 계층형 이름 | 20~25개 | 높이 붕괴 0, 상태 포함 |
| 7 | 화면 | 컴포넌트 | 핵심 화면부터 | 4~6장 | 넘침 0, 화면당 primary 1개 |
| 8 | 상태·플로우 | 화면 | 빈/로딩/에러/부분성공 + 3~4 플로우 | 상태·플로우 | 상태 4종, 플로우 3개 이상 |
| 9 | 검증 | 전체 | 수치 감사 + 금지 규칙 | 검증 로그 | 위반 0 |
| 10 | 핸드오프 | 전체 | 토큰표·컴포넌트·CSS 매핑·열린 이슈 | 1장 | 매핑 완료 |

## 3. 5가지 불변 규칙 (어떤 프로젝트에도 적용)

1. **단일 진실**: 디자인 계획안(`DESIGN-PLAN.md`)이 방향을 정한다. 방향 제시형 스킬은 0개.
2. **토큰 없이 화면 금지**: 모든 색·간격·타이포는 변수/스타일로 먼저 만든다. hex 하드코딩 금지.
3. **컴포넌트 없이 화면 금지**: 같은 버튼을 두 번 만들지 않는다. Auto Layout + 계층형 이름.
4. **프레임 생성 직후 넘침 수치 감사 → 0**: `clipsContent` 때문에 넘친 요소가 조용히 사라진다.
5. **단계별 보고 후 정지**: "만든 것 / 검증 숫자 / 다음"만 보고하고 멈춘다. 확실하지 않으면 질문한다.

## 4. 품질 공식 (검증 가능한 것만)

- 모든 색: Variable 바인딩.
- 모든 프레임: 자식이 프레임 밖으로 나가지 않음(좌표 계산).
- 화면당 primary 액션 1개.
- 본문 대비 4.5:1 이상, focus-visible 2px, 최소 클릭 32×32.
- 상태 4종: 빈 / 로딩 / 에러 / 부분성공.
- 숫자·시간·로그는 Mono. 한국어 라벨, 번역투 금지.
- 금지: 이모지 아이콘, 보라→파랑 그라데이션, 글래스모피즘, 네온, 3단 그림자,
  카드 안 카드, 정보 6줄 초과, 화면당 80단어 초과, `transition: all`, width/height 애니메이션.

## 6. 도구 정책 (D46식)

| 레이어 | 정책 |
|---|---|
| 방향 제시 | **0개** — 계획안이 단일 진실. 테마 뽑기형 스킬은 톤을 흔든다 |

## 7. 디자인 계획안 최소 템플릿 (C-2)

계획안이 없으면 아래 10항목으로 먼저 작성하고 승인받는다.

1. 브랜드 방향 1문장 + 슬로건 + 톤 3단어
2. 컬러 토큰: primitive 이름/hex + semantic 이름(역할) — 다크/라이트 각각
3. 타이포: 스타일명 / 크기 / 행간 / 자간 / 용도 8~10종
4. 스페이싱(4px 그리드) + 라디우스 + 엘리베이션
5. 컴포넌트 인벤토리 20~25개 (이름 / 변형 / 상태)
6. 화면 명세 S0~Sn: ASCII 목업 + 요소 요구표 + 상태(빈/로딩/에러/부분성공)
7. 핵심 플로우 3~4개
8. 모션 스펙
9. 금지·주의 표
10. 리뷰 체크리스트

규칙: 화면당 primary 1개, 정보 6줄 이하, 이모지 아이콘 금지.

## 8. 복사용 프롬프트 (새 프로젝트에 붙여넣기)

`{{...}}`를 대상 프로젝트 값으로 치환한다. `{{TOOL_MODE}}`는 `Figma MCP` 또는 `브라우저/컴퓨터 유즈`.

```text
[역할]
너는 "디자인 공식"을 실행하는 시니어 프로덕트 디자이너다.
이 작업의 목표는 특정 스타일을 복제하는 것이 아니라,
문서 → 계획 → 토큰 → 컴포넌트 → 화면 → 검증 → 핸드오프의 공식을
대상 프로젝트에 그대로 적용하는 것이다.

[대상]
- 프로젝트: {{PROJECT_NAME}}
- PRD: {{PRD_PATH}}
- 디자인 계획안: {{DESIGN_PLAN_PATH}}   (없으면 "없음"이라고 답하고 1단계에서 C-2를 실행)
- Figma 파일: {{FIGMA_URL}}
- 실행 도구: {{TOOL_MODE}}   (Figma MCP 또는 브라우저/컴퓨터 유즈)
- 기준 해상도: {{FRAME_SIZE}}   (기본 1440×900)

[불변 규칙]
1. 디자인 계획안이 단일 진실이다. 다른 프로젝트의 색·화면·카피를 가져오지 않는다.
2. 토큰 없이 화면을 만들지 않는다. hex 하드코딩 금지.
3. 컴포넌트 없이 화면을 만들지 않는다. 같은 요소를 두 번 만들지 않는다.
4. 프레임 생성 직후 넘침을 수치로 감사하고 0으로 만든다.
5. 각 단계가 끝나면 "만든 것 / 검증 숫자 / 다음 단계"만 보고하고 멈춘다.
6. 확실하지 않으면 만들지 말고 질문한다.
7. 도구 이름을 지어내지 않는다. 사용 가능한 도구를 먼저 확인한다.

[10단계 공식]
0. 문서 읽기
   - PRD와 디자인 계획안을 끝까지 읽고 화면 목록·토큰·컴포넌트·금지 규칙을 표로 뽑는다.
   - 문서에 없는 값은 "미정"으로 표시하고 질문한다.
   - 산출: 1장 요약. 아직 만들지 않는다.

1. 계획
   - 디자인 계획안이 없으면 C-2 형식으로 먼저 작성한다.
   - 화면 명세(S0~Sn), 토큰, 컴포넌트 20~25개, 플로우 3~4개, 금지표, 리뷰 체크리스트.
   - 승인 전 Figma를 건드리지 않는다.

2. 프로브
   - 플랜 한도(페이지 수·변수 모드 수), 사용 가능 폰트, 도구 목록을 확인한다.
   - 폰트 폴백을 결정한다. 산출: 프로브 표.

3. 페이지
   - 한도에 맞춰 페이지를 압축한다(Starter=3: Design System / Screens / Handoff).
   - 초과 생성 금지.

4. 토큰
   - Primitives → Semantic Color(다크) → Color Light(라이트 별도)
     → Spacing → Radius → Text Styles.
   - 모든 색을 변수에 바인딩. 산출: 변수 개수·스타일 목록.

5. 기초 보드
   - 브랜드 / 컬러 / 타이포 / 스페이싱·라디우스 보드.
   - 넘침 0.

6. 컴포넌트
   - Auto Layout, 계층형 이름(Button/Primary), 변형·상태 포함.
   - 버튼 → 인풋 → 상태 → 챗 → 카드 → 내비 순서.
   - 높이 붕괴 0.

7. 화면
   - 핵심 화면부터(S1 → S2 → S3 → 나머지).
   - 기준 해상도, 120px 간격 그리드, 화면당 primary 1개.
   - 넘침/겹침 0.

8. 상태·플로우
   - 빈/로딩/에러/부분성공 + 핵심 플로우 3~4개.

9. 검증
   - 모든 색 변수 바인딩, 모든 프레임 넘침 0, primary 1개, 대비 4.5:1.
   - 금지 규칙 위반 0.

10. 핸드오프
   - 토큰 표, 컴포넌트 인벤토리, 구현 매핑(React/Tailwind/shadcn/CSS 변수), 열린 이슈.

[검증 규칙]
- 색: Variable 바인딩 여부.
- 프레임: 자식이 밖으로 나가지 않는지.
- 화면당 primary 1개.
- 이모지 아이콘·보라→파랑 그라데이션·글래스모피즘·네온·카드 안 카드 금지.
- 정보 6줄 초과·화면당 80단어 초과·transition: all 금지.
- 숫자·시간·로그는 Mono. 한국어 라벨, 번역투 금지.

[보고]
각 단계: 만든 것 / 검증 숫자 / 다음 단계.
막힌 것: "차단됨 + 사유 + 우회안".
보고 후 멈춘다. 내가 "계속"이라고 할 때만 다음 단계로 간다.

[첫 응답]
0단계만 수행하고,
① 화면 목록 ② 토큰 ③ 컴포넌트 ④ 금지 규칙 ⑤ 미정 값
만 보고하고 멈춰라.
```

## 9. 적용 순서 (새 프로젝트)

1. **PRD**를 읽고 화면·상태·수용 기준을 확인한다.
2. `DESIGN-PLAN.md`가 없으면 **7번 템플릿(C-2)**으로 작성하고 승인받는다.
3. **8번 프롬프트**의 `{{...}}`를 치환해 새 세션에 붙여넣는다.
4. 0단계 보고 → "계속" → 1단계… 순서로 **한 단계씩** 진행한다.
5. 첫 검증은 작은 화면 1개로 워크플로를 확인한 뒤 전체로 확장한다.

> 결과물의 색·화면·카피는 **대상 프로젝트의 계획안**이 결정한다.  
> 이 스킬은 그 계획안을 "토큰 → 컴포넌트 → 화면 → 검증 → 핸드오프"로 **실수 없이 실행**하는 방법이다.
